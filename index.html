建议落地顺序（不造轮子）

1
P0 · 反向通道补齐（ServerRequest 形状）

把「问人 / 审批 / 打开终端 / 看图」做成内核可发起的宿主请求。Codex 用 item/tool/requestUserInput、item/*Approval；我们已有审批事件，缺的是 write_stdin / view_image 的宿主回调契约。

2
P0 · 终端统一执行族

对齐 command/exec + /write + /resize + /terminate，模型侧对齐 exec_command / write_stdin（unified_exec）。现在只有一次性 command/exec（非 PTY）。

3
P1 · multi_agent_v1 工具命名空间

Codex 是命名空间工具：spawn_agent / send_message / wait_agent / list_agents / interrupt_agent / close_agent…。我们有 agent_<name> 一次性调用，缺生命周期管理面。

4
P1 · goal 方法名对齐

Codex： thread/goal/get|set|clear。我们： goal/set|pause|resume|advance|clear（能力更强，但方法名不同）。补 get，并做别名兼容，桌面可直接按 Codex 名调。

5
P1 · view_image + 多模态入历史

模型工具 view_image；依赖 L0 图片消息。桌面 BrowserPane/附件已有壳，缺内核工具与事件。

6
P2 · web_search / browser_use

Codex web_search 是 hosted tool；browser/computer use 走 ServerRequest + 宿主驱动。内核定义 Tool 契据，执行委托宿主或外部 MCP，不自研浏览器内核。
