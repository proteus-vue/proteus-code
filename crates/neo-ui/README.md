# neo-ui

品牌主题：把语义调色板装进 GPUI 的主题系统。

## 先说清楚它是什么

**它是一个主题，不是一个组件库。** 这一点必须写在最前面，因为目录名容易让人
期待更多。当前内容：

- `apply_neo_theme` —— 把色板装进全局主题（唯一入口）
- `neo_color` —— 语义色调 → 颜色
- `base_bg` / `panel_bg` —— 背景色

组件本身来自组件库（`neo-ui-kit::component`）。**不要**在这里找按钮或表格。

## 用法

```rust,ignore
// `apply_neo_theme` 需要一个真实的 `App`，因此**不能**当文档测试跑。
// 但它必须出现在示例里 —— 它是本 crate 唯一的入口，示例不提到它，
// 读者会以为取色函数就是全部用法。
use neo_ui::apply_neo_theme;

// 建窗口之前、每个 App 上只调一次
fn setup(cx: &mut neo_ui_kit::gpui::App) {
    apply_neo_theme(cx);
}
```

之后用语义色调取色，**不要写字面色值**：

```rust
// 取色不依赖 App，可以在这里验证
let primary = neo_ui::neo_color(neo_text::Tone::Primary);
let bg = neo_ui::base_bg();
let panel = neo_ui::panel_bg();
// 背景色必须与正文色不同 —— 否则会画出"白底白字"（这正是
// 单独提供 base_bg/panel_bg 而不是复用 Tone::None 的原因）
assert_ne!(bg, primary);
let _ = (primary, panel);
```

### 背景色为什么是单独的函数

`neo_color(Tone::None)` **不是**背景色。`Tone::None` 的语义是"未指定，
继承宿主默认前景色"，它兜底到正文色（近白）—— 当底色用会画出白底白字。

所以背景有专门的入口，名字也直说它是背景：`base_bg()`、`panel_bg()`。
这个区分是被坑出来的：语义枚举里总会有"未指定"，把它当作"某个具体颜色"
使用是一个很容易犯、且只在运行时看得出来的错误。

### 换颜色的顺序有依赖

主题系统里有两层：语义色（`colors`）与由它派生的记号（`tokens`）。
渲染读的是**派生层**。因此只改语义色而不重建派生层，界面用的还是旧底色，
而且**不会报错** —— `apply_neo_theme` 内部按正确顺序做完全部四步：

1. 切到深色模式（默认装的是浅色）
2. 覆盖语义色
3. **重建派生记号**（漏掉这步界面颜色不变）
4. 同步基础层（滚动条、拖拽柄是另一份拷贝）

自己改主题时若跳过第 3 步，会得到"改了没反应"的现象。

## 颜色只有一个来源

所有颜色从语义调色板派生，**本 crate 不出现字面色值**。
理由有两个，缺一不可：

- 换主题只需改一处；
- 多个界面（等宽终端 / 不同 GUI 后端）用同一份品牌色 —— 否则同一条内容
  换个界面就变个颜色。

本项目有守卫检查各界面不写字面色值。若你要在自己的工程里复用本主题，
可以直接改调色板，或者自己写一份 `apply_*_theme` —— 后者的成本很低，
它只有几十行。

## 诚实边界

- **不是组件库**（重复一次，因为它最容易被误解）。
- 组件的外观定制（圆角、间距、字号）**不在本 crate 内**：
  那属于组件库的样式体系。本 crate 只管颜色。
- 只提供深色。调色板是深色的（正文色比底色亮得多）。
  要浅色主题应当另写一份 —— 把深色调色板"反转"得到的浅色通常对比度不达标，
  有测试断言当前调色板确实是深色，以免有人误以为是通用的。
- **一个已知的待解问题**：真要把这一层开源，需要先决定语义色调的定义
  随不随主题一起走（它目前来自另一个文本语义 crate）。这不是技术障碍，
  是尚未拍板的取舍。
