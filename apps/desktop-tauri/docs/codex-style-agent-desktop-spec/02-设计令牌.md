# 02 设计令牌

所有色值为从三家解包 CSS 中提取的实测值。右侧"推荐基线"是本方案给的实现值。

---

## 2.1 底色与文字（暗色主题）

| 语义 | Codex `[C]` | MiMo `[M]` | ZCode `[Z]` | 推荐基线 |
| --- | --- | --- | --- | --- |
| 应用底 | `var(--gray-900)` / VS Code 主题 | `#181818` | `oklch(14.5% 0 0)` ≈ `#0a0a0a` | `#141414` |
| 面板/卡片 | `var(--vscode-menu-background)` | `#181818` | `#161616` | `#1c1c1c` |
| 侧栏底 | `var(--vscode-sideBar-background)` | `#181818` | `#161616` | `#171717` |
| 主文字 | `var(--vscode-foreground)` | `#f4f4f5` | `var(--color-neutral-200)` | `#f2f2f2` |
| 次文字 | `color-mix(vscode-fg 65%, transparent)` | `#151c13cc` | `var(--color-neutral-400)` | `#a1a1a1` |
| 分隔线 | `color-mix(oklab vscode-fg 8%, transparent)` | `#2e2e2e` | `#0a0a0a1a` | `#2a2a2a` |

**观察**：三家暗色底都落在 `#0a0a0a`–`#181818` 这个很窄的区间，都不是纯黑。这是这类产品"高级感"的来源——**不要用 `#000`**。

## 2.2 底色与文字（亮色主题）

| 语义 | MiMo `[M]` | 推荐基线 |
| --- | --- | --- |
| 应用底 | `#fffefd` / `#fcfcfd` | `#fcfcfc` |
| 面板 | `#fff` / `#fdfdfd` | `#ffffff` |
| 主文字 | `#151c13cc` | `#18181b` |
| 分隔线 | `#f0ebe5` / `neutral-100` | `#ececec` |

亮色底同样不是纯白，都带一点点暖/冷偏移。

## 2.3 强调色与语义色

| 语义 | 实测 | 推荐基线 |
| --- | --- | --- |
| 品牌强调 | MiMo `#ff6a2b`（橙）`[M]`；ZCode `sky` 系 `[Z]` | 自选，但**必须只有一处高饱和强调色** |
| diff 新增 | MiMo `#3fb950` / `#1a7f37` `[M]` | `#3fb950` |
| diff 删除 | MiMo `#e5484d` `[M]` | `#e5484d` |
| 成功 / 警告 / 错误 | Tailwind v4 内置 `[C][M][Z]` | 直接用内置 |

> **注意**：diff 的红绿不要反转。中文语境下「新增=绿、删除=红」是代码 diff 的通用约定（不同于股市红涨绿跌）。

## 2.4 尺寸标度

| 项 | Codex `[C]` | MiMo `[M]` | ZCode `[Z]` | 推荐基线 |
| --- | --- | --- | --- | --- |
| 间距基数 `--spacing` | `.25rem` | `.25rem` | `.25rem` | `.25rem`（Tailwind v4 默认） |
| 圆角 `--radius-md` | `.5rem` | `.375rem` | — | `.5rem` |
| 圆角 `--radius-lg` | — | `.5rem` | — | `.75rem` |
| 卡片圆角 | — | `12px` `[M]` | — | `12px` |
| Toolbar 高度 | `46px` `[C]` | — | — | `46px` |
| 侧栏宽度 | `clamp(240px, …)` `[C]` | `rail 62 + sw 194 = 256px` `[M]` | — | `256px`（折叠态 `62px`） |
| 消息流最大宽 | `40rem` / `42rem` `[C]` | — | — | `40rem`（≈640px） |
| 正文基础字号 | `--text-base: 14px` `[C]` | — | — | `14px` |
| 对话正文字号 | `--codex-chat-font-size: 16px` `[C]` | — | — | `16px` |
| 代码字号 | `var(--vscode-editor-font-family)` `[C]` | — | — | `13px`，等宽 |

**关键观察**：正文 `14px`、对话内容 `16px`——**对话区比 UI 其他部分字号大**。这是可读性的关键，别统一成 14px。

## 2.5 圆角策略（Codex 的独门细节）

Codex 有一套可缩放的圆角体系 `[C]`：

```css
--codex-corner-shape: superellipse(1.5);   /* 超椭圆，Apple 风格 squircle */
--codex-corner-radius-scale: 1.25;
--radius-sm: calc(var(--radius-sm-base) * var(--corner-radius-scale));
```

它把每个圆角都乘一个全局 scale，并提供 `round` / `superellipse(1.5)` 两种形状。**建议至少实现 scale 那一层**（一个变量控制全局圆角松紧），这是低成本高收益的设计感来源。

## 2.6 编辑器与代码区配色

三家都沿用 VS Code 主题变量体系（实测命中：Codex 14 处、MiMo 77 处、ZCode 1 处）`[C][M][Z]`：

```css
--font-mono: var(--vscode-editor-font-family, var(--font-mono-default));
--code-font-size: var(--vscode-editor-font-size, 13px);
```

**建议**：代码区（diff、代码块、终端）直接用 VS Code Dark+ 的 token 配色（或 Shiki 的 `github-dark`），这样用户看到的语法高亮和他们编辑器里一致，认知负担最低。不要自创一套代码配色。

## 2.7 关于"抄配色"的判别

实测发现三家 CSS 变量交集里 **87–88% 的值完全相同**，但那些全部是 **Tailwind v4 内置调色板**，例如：

```
--color-green-500 = oklch(72.3% .219 149.579)    三家一字不差
--animate-pulse   = pulse 2s cubic-bezier(.4,0,.6,1) infinite
--blur-md         = 12px
```

**结论**：这些不是抄袭痕迹，是同一个生成器产物。真正体现设计血统的是语义层令牌（surface / border / 侧栏宽度 / 字号），上表已经把它们单独拎出来了。**照着上表的"推荐基线"实现即可，不必去逐条对齐任何一家的内置调色板。**

## 2.8 字体

| 来源 | 实测字体栈 |
| --- | --- |
| Codex `[C]` | `--font-sans: var(--vscode-font-family, var(--font-sans-default))` |
| MiMo `[M]` | `--font-sans: var(--font-fallback-sans)` |
| ZCode `[Z]` | `ui-sans-serif, system-ui, sans-serif, "Apple Color Emoji", …` |

**推荐**：用系统字体栈，不要打包自定义字体（省体积、无授权风险）。中文务必显式补 `PingFang SC` / `Microsoft YaHei`。

```css
--font-sans: ui-sans-serif, system-ui, -apple-system, "PingFang SC",
             "Microsoft YaHei", sans-serif;
--font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas,
             "PingFang SC", monospace;
```
