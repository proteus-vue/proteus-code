# 07 隐私与遥测红线

> 判定口径来自一次真实的行业事件（某客户端在登录后静默打包整个工作区并加密上传，开关关不掉）。
> 本章把那次事件的**特征**固化成检查表，避免重蹈覆辙。

---

## 7.1 绝对禁止项

| # | 禁止 | 说明 |
| --- | --- | --- |
| 1 | **静默打包工作区上传** | 无论加密与否。含 `.git` 目录尤其严重 |
| 2 | **把私钥放在云端、公钥在客户端的加密上传通道** | 用户无法解密 = 数据单方面流出 |
| 3 | **开关关不掉的遥测** | 有开关但默认开且无法关闭，等同于没有开关 |
| 4 | **上传代码内容、文件路径、diff** | 包括"为了改进模型"的名义 |
| 5 | **上传完整对话内容** | 除非用户主动点"分享"或"反馈" |
| 6 | **在登录/首次启动时触发批量上传** | 用户还没同意任何事 |

## 7.2 自查特征串

实现完成后，在整个代码库里 grep 以下特征串，**任何一项出现都要能给出正当理由**：

```
repo_snapshot  repoSnapshot  codebase_index  repoWiki
uploadCredential  pendingUpload  activeUpload
tar.gz.enc  envelope.json  rsa-oaep  aes-256-ctr
presigned  multipart  oss-cn
```

对照结果：MiMo 全树**全部 0 命中**（其 `aes-256-ctr` 仅出现在前端 xlsx 转换与 browserify crypto，与上传无关）。

## 7.3 遥测：如果一定要做

| 要求 | 说明 |
| --- | --- |
| **默认关闭** | 首次启动时询问，不询问就默认关 |
| **可关闭** | 设置页有明确开关，且开关真的生效（代码里读这个开关） |
| **只发元数据** | 允许：模型 ID、token 数、耗时、工具名、输入/输出**字节数** |
| **禁止发内容** | 代码、路径、diff、会话标题、文件名的明文 |
| **会话 ID 哈希** | 上报前做哈希，不要发原始 ID |
| **端点可查** | 在设置页写明上报到哪个域名 |

实测参考：MiMo 引擎层遥测被桌面端通过主进程注入 env 主动关闭（`MIMOCODE_ENABLE_ANALYSIS: "false"`），但其 UI 层遥测仍默认开且**无关闭开关**——这是它唯一需要提示的点 `[M]`。ZCode 侧有 `@arms` RUM 相关依赖 `[Z]`。

**正确做法**：**两层都要能被同一个开关关掉。**

## 7.4 高权限能力：需要额外告知

这些能力本身不是问题，但必须让用户知情并主动开启：

| 能力 | 权限 | 要求 |
| --- | --- | --- |
| 浏览器桥接扩展 | `<all_urls>` + `debugger`，能读所有已登录页面 | 默认不安装；安装时明确告知风险 |
| Computer Use（截屏/键鼠控制） | 无障碍、屏幕录制 | 每次使用需授权；有可见的运行指示 |
| 本地 HTTP API | 本机端口监听 | token 不应明文落盘；默认只监听 127.0.0.1 |

实测：MiMo 的 Browser Bridge manifest 含 `debugger` + `<all_urls>` `[M]`；本地 API 的端口与 token 明文写在配置文件里。

**规范**：本地 API 默认只监听回环地址，token 随机生成且密钥链存储优先于明文文件。

## 7.5 云端下发配置

如果客户端会拉取云端配置（feature gate 之类），必须：

1. 明确告知用户存在云端可控开关
2. 云端配置**不能**覆盖安全相关的本地策略（权限、遥测开关）
3. 拉取失败时回退到本地默认，不能卡死

## 7.6 上线前的隐私自检

| # | 检查项 | 通过 |
| --- | --- | --- |
| 1 | 全库 grep 7.2 的特征串，无异常命中 | ☐ |
| 2 | 首次启动无任何批量上传行为（抓包验证） | ☐ |
| 3 | 遥测默认关闭，且设置页开关真实生效 | ☐ |
| 4 | 遥测上报字段不含代码/路径/diff/会话内容 | ☐ |
| 5 | 会话分享默认关闭，需用户主动触发 | ☐ |
| 6 | 高权限能力默认关闭，开启时有明确告知 | ☐ |
| 7 | 本地 API 只监听 127.0.0.1，token 不明文落盘 | ☐ |
| 8 | 文档里写明数据目录位置与什么会外传 | ☐ |

## 7.7 验证方法（交给用户也能复现）

静态检查只能证明代码里有什么，运行时行为要抓包：

```bash
# 查看应用当前建立的连接
lsof -nP -iTCP -sTCP:ESTABLISHED | grep -i <app>

# 查看应用实际打开了哪些本地文件
lsof -c <app> | grep -v "\.app/" | head -50
```

**建议把这两条写进你的 README**，让用户能自己验证。信任是靠可验证建立的。
