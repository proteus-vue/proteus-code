# 06 数据与配置规范

## 6.1 目录约定

三家都是双目录：配置在一个，状态/数据在另一个。

| 来源 | 配置目录 | 数据目录 |
| --- | --- | --- |
| MiMo `[M]` | `~/.config/mimocode/` | `~/.local/share/mimocode/` |
| ZCode `[Z]` | `~/.zcode/v2/` | — |
| Codex `[C]` | `~/.codex/` | — |

**推荐**：

```
~/.config/<app>/          配置（用户会手改的）
  config.jsonc            主配置（jsonc 支持注释）
  agents/                 自定义 agent 定义
  skills/                 技能
~/.local/share/<app>/     状态（应用自己写的）
  <app>.db                会话持久化（SQLite）
  auth.json               凭据（权限 600）
  log/                    日志
  snapshot/               会话快照（用于回退）
~/Library/Application Support/<app>/   （macOS）窗口状态、缓存
```

## 6.2 配置合并顺序（易踩坑）

实测 MiMo 的顺序 `[M]`：

```
全局 ~/.config/mimocode/mimocode.jsonc
  → $MIMOCODE_CONFIG （环境变量指定的配置）
    → 项目级 mimocode.json
      → $MIMOCODE_CONFIG_CONTENT  ★ 桌面端注入，最后覆盖，优先级最高
```

**坑**：桌面端在启动时注入 `CONFIG_CONTENT`，它**最后合并**，会覆盖你在配置文件里写的所有同名项。实测 MiMo 注入的内容里含 `experimental.continue_loop_on_deny: true`，用户在配置文件里改成 false 也没用。

**规范**：

1. 合并顺序必须**文档化**，并在设置页能显示"当前生效值来自哪一层"（诊断视图）。
2. **不能被用户覆盖的都是坏设计**。任何由客户端注入的默认值，都要允许被用户配置或环境变量覆盖。
3. 不要把实验性开关硬编码注入。

## 6.3 凭据存储

- 配置文件权限必须是 `600`。
- API Key 在 UI 上默认密文显示，复制需显式点击。
- 不要把凭据写进日志。日志输出时对 key 做脱敏（保留前 4 位）。

## 6.4 会话持久化

用 SQLite（三家都用）。建议表结构：

```
session   (id, title, project_path, model, created_at, updated_at, parent_id)
message   (id, session_id, role, created_at)
part      (id, message_id, type, content, metadata)   -- type: text/tool/reasoning/diff/error
```

**为什么拆 `part`**：一条消息里可能有文本 + 多个工具调用 + diff，拆开才能做细粒度渲染与重试。MiMo 实测就是 `session / message / part` 三级 `[M]`。

## 6.5 会话快照与回退

- 每个会话的改动用 **git** 记录（可以是临时仓库或 worktree），不要自己发明一套快照格式。
- 实测 MiMo 的 `~/.local/share/mimocode/snapshot/` 是**本地 git 对象库**，每会话一个仓库，用于 checkpoint 回滚 `[M]`。这个设计是对的：**本地、不加密、不上传**。
- 提供"回退到某个消息之前"的能力。

## 6.6 日志

- 日志分级，默认 INFO；提供 DEBUG 开关。
- 日志里**不得**出现：完整文件内容、diff 全文、API Key。
- 日志轮转，避免无限增长。

## 6.7 环境变量命名

统一前缀，避免污染：

```
<APP>_CONFIG            指定配置文件路径
<APP>_CONFIG_CONTENT    注入配置内容（谨慎使用，见 6.2）
<APP>_DISABLE_*         关闭某能力
```

**规范**：环境变量透传给引擎时必须用 `{...process.env}` 全量，不要用白名单构造——白名单会让外部注入失效。
