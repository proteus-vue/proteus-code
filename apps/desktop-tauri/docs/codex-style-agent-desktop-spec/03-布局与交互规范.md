# 03 布局与交互规范

## 3.1 主骨架

```
┌──────────┬────────────────────────────────────┬──────────────┐
│          │ Toolbar                     46px    │              │
│ Sidebar  ├────────────────────────────────────┤   Panel       │
│  256px   │                                    │  resizable    │
│ (折叠    │      Message stream                │  ≥320px       │
│  62px)   │      max-width 40rem, 居中          │              │
│          │                                    │ diff / 终端  │
│ 会话列表 │                                    │ / 预览 / 文件 │
│ 项目列表 │                                    │              │
│          ├────────────────────────────────────┤              │
│          │ Composer                           │              │
│          │  输入框 + 模式选择 + 附件 + 发送    │              │
└──────────┴────────────────────────────────────┴──────────────┘
```

尺寸实测：`--toolbar-height: 46px` `[C]`；侧栏 MiMo `rail 62px + sw 194px = 256px` `[M]`，Codex `clamp(240px, …)` `[C]`；内容区 `max-width: 40rem`（另见 42rem 变体）`[C]`。

## 3.2 各区域职责

| 区域 | 职责 | 必备能力 |
| --- | --- | --- |
| **Sidebar** | 会话列表、项目/仓库切换 | 新建、重命名、删除、搜索、置顶、按项目分组 |
| **Toolbar** | 上下文信息 + 全局操作 | 当前模型、当前目录/分支、权限模式、上下文余量、设置入口 |
| **Message stream** | 对话主体 | 用户消息、助手 Markdown、工具调用卡片、diff、审批请求、错误 |
| **Panel** | 工作区细节 | 文件 diff、终端、预览、文件树；可拖拽调宽，可折叠 |
| **Composer** | 输入 | 多行输入、@ 引用文件、图片附件、模型选择、权限模式、发送/停止 |

## 3.3 消息流的关键交互

1. **工具调用必须折叠成卡片**，默认展示工具名 + 关键参数 + 状态，点击展开完整输入输出。不要把所有输出平铺出来。
2. **流式渲染**：逐 token 追加，Markdown 增量解析（推荐 `@streamdown` 这类流式 Markdown 库，ZCode 用了 `[Z]`）。
3. **长输出截断**：单条工具输出超过阈值（建议 30KB）折叠为"查看完整输出"。
4. **自动滚动**：用户手动上滑后停止自动滚动，底部出现"回到底部"。
5. **中断**：任何时刻可停止，停止后立即落盘已产生的内容，不要丢上下文。

## 3.4 快捷键

MiMo 实测 35 个快捷键 `[M]`。以下是必须有的：

| 快捷键 | 作用 |
| --- | --- |
| `⌘N` | 新建会话 |
| `⌘K` / `⌘P` | 命令面板 / 快速跳转 |
| `⌘⇧K` | 清空当前会话 |
| `⌘,` | 设置 |
| `⌘B` | 折叠/展开侧栏 |
| `⌘J` | 折叠/展开右侧面板 |
| `⌘/` | 快捷键速查 |
| `⌘⇧O` | 切换权限模式 |
| `⌘L` | 聚焦输入框 |
| `⌘⏎` / `⏎` | 发送（建议 `⏎` 发送、`⇧⏎` 换行，并提供设置项反转） |
| `Esc` | 停止当前生成 |
| `⌘⇧C` | 复制最后一条回复 |

**原则**：所有快捷键可查看、可改（至少可查看）。别做成黑盒。

## 3.5 响应式与窗口

- 最小窗口宽度建议 `900px`（低于此面板区应自动折叠）。
- Codex 有 `--codex-window-zoom: 1.25` `[C]`，即整体缩放档位——成本很低，建议实现一个 1 / 1.25 两档。
- 窗口位置与尺寸持久化（ZCode 有 `macos-window-bounds` 目录 `[Z]`）。

## 3.6 空状态与引导

三个空状态必须单独设计：
1. 无会话（首屏）：一句引导 + 输入框 + 最近项目
2. 会话已创建但未发消息：建议提示（可直接用项目里的 README / AGENTS.md 作为上下文）
3. 工具执行中：明确的进行中指示 + 已耗时 + 可中断

**别让首屏是空白面板**，这是新用户流失的第一原因。

## 3.7 视觉一致性的几条硬规则

1. **暗色底不要用 `#000`**：三家实测全在 `#0a0a0a`–`#181818`。
2. **对话正文字号 16px，UI 正文 14px** `[C]`：不要统一。
3. **全局只留一处高饱和强调色**（MiMo 是橙 `#ff6a2b` `[M]`）。强调色一多就廉价。
4. **代码区沿用 VS Code Dark+ 配色**（三家都这么做 `[C][M][Z]`），不要自创。
5. **圆角用一个 scale 变量统一控制**（Codex 的做法 `[C]`），后续调风格只改一处。
