# 执行摘要（一页纸）

## 目标
重构 DSH，产出 **NEO**：Rust 内核 + Web/TUI 双宿主的编程 Agent。

## 吸收什么

### 来自 智谱 ZCode（交互层，主体闭源，只借鉴可观测的交互范式）
| 设计 | 为什么值得抄 |
|---|---|
| **Goal Mode**（`/goal`） | 把"一次一提示"升级为"持久化目标"：自动拆解子任务 → 执行 → 自验证 → 迭代；可暂停/重定向/断点恢复，不重置会话 |
| **五种执行模式** | 默认 / 变更前确认 / 自动编辑 / 计划模式 / 完全访问。核心逻辑：**自主程度与信任度正相关** |
| **`@` `#` `/` `$` 引用体系** | `@`文件、`#`历史会话、`/`命令、`$`技能 —— 把"上下文装配"从模型猜变成用户显式指定 |
| **任务线程化** | 多个 Goal 并发，各自独立进度面板（耗时 / token / 迭代数） |
| **AGENTS.md 项目约定** | 项目级指令文件，团队共享 |

### 来自 OpenAI Codex CLI（架构层，Apache-2.0，可对照实现）
| 设计 | 为什么值得抄 |
|---|---|
| **多宿主共享内核** | 一份 core 服务 CLI / TUI / Exec / App-Server / MCP —— NEO 取 Web + TUI + Exec |
| **SQ / EQ 事件队列** | `submit(Op)` 与 `next_event()->EventMsg` 解耦宿主与引擎；天然可录制、可回放、可审计 |
| **沙箱 × 审批 正交双轴** | 3 档沙箱（read-only / workspace-write / danger-full-access）× 4 档审批（untrusted / on-request / on-failure / never） |
| **OS 级沙箱** | macOS Seatbelt、Linux Landlock+bwrap+seccomp、Windows restricted token+ACL |
| **Shell-First 工具哲学** | 一个 bash 执行器替代数百专用工具；文件变更只走 `apply_patch` 专用信封 |
| **四级配置 + AGENTS.md 级联** | 内置 → 系统 → 用户 → 项目 → CLI flag |

## 摒弃什么（DSH 的冗余过重设计）

| # | 摒弃项 | 理由 |
|---|---|---|
| 1 | **"一切皆插件"（含 agent loop / UI / 存储插件化）** | 调用栈过深、错误定位极难，是 AI 辅助开发的最大阻碍 |
| 2 | **219 个 workspace 包** | 粒度失控，改一处跨 N 包，构建与认知成本双高 |
| 3 | **100+ 插件默认全量加载** | 冷启动与配置面巨大 |
| 4 | **4 种预制运行模式**（Standard/PTC/Minimal/Creator） | 模式 = 插件集的笛卡尔组合，边界模糊、能力重叠 |
| 5 | **vendor Cordis 9 个包 + 18 条本地修改** | 与上游 Cordis 脱钩，长期维护债 |
| 6 | **社区 Electron 桌面壳** | 78MB+ 包体，进程/端口/托盘全是胶水，与 Node 内核重复 |
| 7 | **PTC 模式的额外 TS 脚本运行时** | 与沙箱叠加，复杂度不成比例 |

## 替换成什么

```
摒弃"一切皆插件"  →  固定六层内核 + 4 类有限扩展点
摒弃 4 种运行模式 →  正交双轴：5 档执行模式 × 3 档沙箱（UI 档位映射到审批策略）
摒弃 Electron 壳  →  **系统 webview（wry）** 桌面宿主 + TUI + Web + Exec，
                        四者同为 `HostBackend` SPI（可选 egui 作第二后端）
摒弃「固定内核」措辞  →  **5 个有名 SPI**（Proteus 方法论），不是写死内核
摒弃 219 包       →  12 个 crate，依赖严格单向
```

## 三点五、Electron 换成什么（本版本新增，回答早期版本的空白）

早期版本只写「Web 宿主不需要 Electron」，但**桌面应用仍需要一个窗口**——那句话没回答问题。

结论：换成 **系统 webview（wry）**，不是换另一个壳。

| 宿主后端 | 技术 | 二进制量级 |
|---|---|---|
| `neo-host-tui` | ratatui + crossterm | ~2–5 MB |
| **`neo-host-desktop`** | **wry（系统 webview）** | **~5–10 MB** |
| `neo-host-web` | axum + WebSocket | ~5–10 MB |
| `neo-exec` | 无头 | ~2–5 MB |

对比 Electron 的 **~78 MB+**：系统 webview 不捆 Chromium、不捆 Node。

**为什么是系统 webview 而非纯原生 GUI**：为保住已有投资——现有 React + 液态玻璃界面
在 webview 里**原样可用**（同一引擎，`backdrop-filter` 照常工作）。纯 Rust GUI（egui/gpui）
则要求用 Rust 重写整个 UI，液态玻璃得自己写着色器。

**顺带消灭一整类复杂度**：DSH 包的 `file:`/symlink 陷阱、profile/pnpm/bundle 层叠、
Node ≥22 运行时要求、bundle 改动须重启——全部消失（编译期静态链接、单二进制）。

**但两件事不会消失**（诚实标注）：
1. **DOM/CSS 复杂度仍在**（webview 就是浏览器）。液态玻璃的 `backdrop-filter` 包含块
   副作用、哈希类名不可选等坑依然存在——这些是本会话实测过的。
2. **OS 沙箱三平台差异仍在**，是 NEO 最重的部分。

## 三点六、方法论纲领（新增）

完整见 [`02-架构设计/Proteus方法论-语义核心与后端SPI.md`](02-架构设计/Proteus方法论-语义核心与后端SPI.md)。

一句话：**用 Proteus 的统一语义收敛做 NEO**。语义核心（Op/EventMsg、Turn 状态机、
SessionEvent、Tool 契约、Approval 决策、SandboxMode）固定且平台无关；平台差异下沉为
**5 个受控 SPI**，每个都有契约 + ≥2 后端 + conformance 门禁（机器校验）。

> **DSH 的病不是「插件太多」，而是「seam 没有名字、没有门禁」。**
> NEO 把 ~90 个无名 seam 收敛为 5 个有名 seam —— **同时得到可替换性与可定位性**。

## 三点七、耦合审计（SPI-First Phase 1 实测，2026-09-11）

用 grep 量化「换掉 X 要改多少文件」（详见 [`05-验证/spi-first-audit.md`](05-验证/spi-first-audit.md)）：

| 耦合点 | 业务文件数 | 优先级 |
|---|---|---|
| DSH 内核（`@deepseek-ai/*`） | **8** | P0（用户已决定重写） |
| Electron 壳 | **2**（含 25 处 API 调用） | P1 |

### 关键发现：DSH 耦合只有 8 个文件，是因为**它本身已经是 SPI**

`ctx.tools` / `ctx.shell` / `ctx.llm` / `ctx.commands` / `ctx.skills` 都是 DSH 自己定义的
SPI，我们是**通过接口**接入的，所以耦合面很小。

> **这修正了对 DSH 的判断**：DSH 的问题不是「没有 SPI」，而是 **SPI 太多且无名（~90 个）**，
> 而我们实际只用到 5 个。所以 NEO 的正确定位不是「从零造 SPI」，
> 而是 **把 90 个无名 seam 收敛为 5 个有名的**。

### Electron 只渗进 2 个文件

说明壳层**本来就已经隔离好了**——`HostBackend` 是把这条**已存在的好边界形式化**，
而不是新建边界。**改造风险因此很低**，且 AP-04（业务绕过接口直调底层）的现存漏洞
就在这 2 个文件里，是下一步试点的首选目标。
