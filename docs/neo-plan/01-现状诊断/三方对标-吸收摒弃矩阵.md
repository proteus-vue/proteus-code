## B. 安全层

| 能力点 | DSH | ZCode | Codex | NEO 决策 |
|---|---|---|---|---|
| 沙箱档位 | read-only / workspace-write / danger-full-access | 权限分组 | 同 DSH 三档 | ✅ 保留三档 |
| 沙箱实现 | bwrap/Landlock、seatbelt、write-restricted token | 进程隔离 | Seatbelt / Landlock+bwrap+seccomp / restricted token+ACL | ✅ 三平台 OS 级，Rust 重写 |
| fail-closed | ✅ 无后端直接拒绝 | — | ✅ | ✅ 保留（这是 DSH 的亮点） |
| 审批策略 | 有 | 五档执行模式 | untrusted / on-request / on-failure / never | ✅ **正交双轴** |
| 网络默认 | — | 需确认 | workspace-write 下默认断网 | ✅ 默认断网，显式开启 |

**正交双轴是 NEO 的核心安全设计**：
```
sandbox_mode（能做什么）  ×  approval_policy（何时必须问）
```
二者独立配置。Codex 社区最常见的困惑正是把两个旋钮当成一个调 —— NEO 在 UI 上就要把这点讲清楚。

## E. 上下文策略

| 设计 | 来源 | NEO 决策 |
|---|---|---|
| **固定前缀 + 增量追加**（利于 prompt cache） | Codex | ✅ 全量吸收 —— 系统提示与工具描述必须字节稳定，工具按固定顺序注册 |
| **fresh-by-default**（无关问题从干净上下文开始） | 开源 zcode CLI（LanceDB） | 🔶 吸收思路，实现延后：M4 先用 JSONL + 关键词，M6 后引入向量索引 |
| **预采样检测 → compact** | Codex `run_turn` | ✅ 吸收 |
| **上下文装配显式化**（`@` `#`） | ZCode | ✅ 吸收 —— 减少模型猜上下文 |

> 这与本项目此前确认的"规划先行提高缓存命中"完全一致：**稳定前缀 + 显式上下文**是同一个工程原理。
