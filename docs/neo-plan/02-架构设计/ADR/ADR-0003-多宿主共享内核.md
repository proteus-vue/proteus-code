# ADR-0003：Web + TUI 双宿主共享同一内核（SQ/EQ 事件协议）

- **状态**：已接受
- **关联**：Codex 多宿主架构

## 背景
需要一个桌面友好的 Web 界面，也需要一个高效的终端界面。
若各自实现，业务逻辑必然重复且行为漂移。

## 决策
一份 `neo-core` 同时服务三宿主：**TUI / Web / Exec**。
宿主与引擎之间只通过 **SQ（Submission Queue）/ EQ（Event Queue）** 通信。

```rust
core.submit(op)            // 宿主 → 引擎
core.next_event().await    // 引擎 → 宿主
```

## 理由
1. Codex 已验证此模式可支撑 5 种宿主（CLI/TUI/Exec/AppServer/MCP）。
2. 宿主不持有业务状态 → **改 UI 不碰内核**。
3. Op + EventMsg 序列天然构成**可录制、可回放、可审计**的日志。
4. Web 宿主不需要 Electron（内核是 Rust 单二进制，Web 侧只做渲染 + WS 转发）。

## 代价
- 事件协议要先设计稳，后期改协议成本较高
- 流式 UX 需要 `AgentMessageDelta` 逐块设计

## 验证方式
`check_protocol.py`：golden Op 序列回放，断言 EventMsg 序列确定性。
