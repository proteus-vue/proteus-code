# ADR-0001：放弃"一切皆插件"，改为固定内核 + 4 类扩展点

- **状态**：已接受
- **日期**：2026-09-10
- **关联**：DSH 冗余项 R1

## 背景
DSH 的核心口号是 "Everything is a Plugin"，模型适配器、工具注册表、会话日志、沙箱、存储、agent loop、UI 全部可替换。
这在框架灵活性上是极致，但带来了：极深调用栈、错误定位困难、插件间依赖不可静态分析。

## 决策
NEO 采用**固定六层内核**，只开放 4 类扩展点：
1. `Tool` —— 新能力
2. `Skill` —— 可复用工作流
3. `Subagent` —— 并行分工（Markdown 定义，对齐 ZCode）
4. `ModelProvider` —— 换模型

内核职责（agent loop、状态机、上下文管理、沙箱判定）**不可替换**，只能配置调参。

## 理由
1. **AI 辅助开发时代，可定位性 > 灵活性**。本项目的实际痛点是"AI 改完报错后定位慢"，插件间接化会直接放大这个痛点。
2. 实际需求 95% 落在上述 4 类扩展点内。
3. 换 loop / 换存储 / 换 UI 的需求在实践中极少，但代价（调试成本、认知成本）极高。
4. 固定内核使**依赖方向可静态分析**，从而可用工具强制校验（见 `check_architecture.py`）。

## 代价
- 丧失"整体替换某一层"的极端灵活性
- 若将来确需替换内核某部分，需改内核代码（可接受）

## 验证方式
`check_architecture.py` 强制校验：无向上依赖、无环、L2 不依赖 L3/L4/L5。

## 修正（2026-09-11）：不是「放弃 seam」，而是「收敛 seam」

本 ADR 早期标题容易被读成「把 DSH 的插件全删掉、写死成一段大代码」——那是**另一种极端，同样错**。

按 **Proteus 方法论**（见 `Proteus方法论-语义核心与后端SPI.md`）修正为：

> **DSH 的病不是「插件太多」，而是「seam 没有名字、没有门禁」。**
> 约 90 个 workspace 包 = 90 个**无名** seam：无法静态分析、无法验证可替换性。
> NEO 把 seam **收敛为 5 个有名 SPI**，每个都有契约 + ≥2 后端 + conformance。

| | DSH | 纠偏后 NEO |
|---|---|---|
| seam 数量 | ~90（无名） | **5（有名）** |
| 有契约吗 | 有（Cordis service） | 有（Rust trait） |
| 有 ≥2 后端吗 | 部分，未强制 | **强制**，CI 校验 |
| 有 conformance 吗 | 部分 | **强制**，每 SPI 一套 |
| 依赖可静态分析吗 | 否（运行时查找） | **是**（crate 图 + 守卫） |

**关键结论**：把 90 个无名 seam 收敛成 5 个有名 seam，**同时得到可替换性与可定位性**——
这正是 DSH 缺失的那一半。写死内核反而把可替换性一起丢了。

机器保证：`05-验证/checks/check_spi_conformance.py`（≥2 后端、SPI 数量上限、假 SPI 检测）。
