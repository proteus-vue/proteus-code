# 上下文策略：稳定前缀 + fresh-by-default

> 目标：**最大化 prompt cache 命中**（与前序讨论的"规划先行提高命中"同源），同时避免无关历史污染。

## 三条原则

### 1. 固定前缀，字节稳定

System prompt + 工具描述构成请求前缀，必须**每次请求完全一致**：
- 工具按**固定顺序**注册（禁止 HashMap 随机序）
- 不掺时间戳、随机数、PID、cwd 绝对路径
- 版本号变化时整体失效是可接受的（本来就要失效）

这条决定了缓存能不能命中。**前缀每变一个字节，后面全部 miss。**

### 2. 增量追加，不重写历史

历史消息以 append 方式增长，**不重写、不重排**。
压缩（compact）是**例外事件**，会整体失效一次缓存 —— 所以要**预采样检测**，提前 compact，避免中途触发。

### 3. fresh-by-default（吸收开源 zcode CLI）

新问题进来时，先在本地索引里检索相关历史轮次：
- **无相关** → 从干净上下文开始，只带固定前缀
- **有相关** → 只注入相关的若干轮

好处：
- 避免跨主题污染（"上次聊重构，这次问部署"不该带上一堆重构上下文）
- 减少无效 token

**落地节奏**：
- **M4**：JSONL + 关键词/BM25 检索（够用，零依赖）
- **M6 后**：引入向量索引（可选），索引始终为**派生数据**，可从 JSONL 随时重建

## AGENTS.md 级联（吸收 Codex + ZCode）

```
~/.neo/AGENTS.override.md   ← 始终优先，始终最先加载
~/.neo/AGENTS.md            ← 个人基线
<repo>/AGENTS.md            ← 团队共享
<repo>/sub/dir/AGENTS.md    ← 目录级联，越具体越优先
```
- 每目录最多一个 `AGENTS.md`
- 合并大小上限 **32 KiB**（防滥用）
- 超限 → 让模型生成握手摘要，以 `_summary` 前缀的用户消息存储

## 显式上下文装配（吸收 ZCode `@ # / $`）

| 符号 | 作用 |
|---|---|
| `@path` | 引用文件/文件夹 |
| `#session` | 关联历史会话 |
| `/command` | 调用已保存命令 |
| `$skill` | 触发技能 |

**价值**：把"上下文装配"从"模型猜"变成"用户显式指定" —— 既省 token 又提高准确率。
输入层（L5）负责解析，产出 `Vec<ContextRef>` 随 `Op::UserTurn` 下发。
