# L4 · 目标编排层规格

**crate**：`dsh-orchestration`
**依赖**：L3、L2、L1、L0
**职责**：ZCode Goal Mode 的落地 + 四阶段闭环

## Goal 引擎（吸收 ZCode Goal Mode）

```
/goal "<高层目标>"
   │
   ├─ 意图解析 → 结构化任务树
   ├─ 依赖分析 → 扫描代码库，识别待改模块
   ├─ 任务拆解 → 有序子任务队列
   ├─ 优先级排序（按依赖关系）
   │
   ▼ 执行循环（每个子任务走一遍四阶段）
   ┌───────────────────────────────┐
   │  Plan    → 产出执行计划        │
   │  Code    → ReAct：思考/调工具/ │
   │            观察/重复/汇报      │
   │  Review  → 红绿测试闸门        │
   │  Learn   → 错误归纳为持久纠正  │
   └───────────────────────────────┘
        失败 → 回退到 Code（≤3 次）
        成功 → 下一子任务 + Checkpoint
```

**四阶段来自开源 zcode CLI 的 Plan→Code→Review→Learn**，这是它最值得抄的架构点。

## 关键能力（对齐 ZCode）

| 能力 | 说明 |
|---|---|
| **可暂停** | `Op::GoalPause`，不重置会话 |
| **可重定向** | 中途注入新指令，改变后续计划 |
| **可清除** | 清除 goal 不重置会话 |
| **断点恢复** | Checkpoint 链（见 02-会话状态机与Checkpoint.md） |
| **进度可见** | `GoalProgress { done, total }` 事件 + 耗时/token/迭代数面板 |
| **多 Goal 并发** | 各自独立状态与进度 |

## 停止条件（防失控）
最大迭代 50 / 最长 4h / token 预算 500K / 连败 3 次 / Review 重试 3 次。

## Learn 阶段（易被忽略但很值）
把反复出现的错误归纳为**持久化的纠正笔记**，注入后续 Plan 阶段。
这是从"每次重犯"到"逐渐变聪明"的关键。

## 验收
- [ ] `/goal` 可拆解、可暂停、可恢复
- [ ] 进程 kill 后重启能从 Checkpoint 续跑
- [ ] Review 失败能自动回退重做，≤3 次后停止并上报
- [ ] 停止条件全部生效（不出现无限循环）
