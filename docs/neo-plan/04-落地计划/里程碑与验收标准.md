# 里程碑与验收标准（M0–M6）

> **口径**：每个里程碑都有可执行的验收命令，不是"感觉差不多"。
> 所有可执行校验集中在 `05-验证/verify.sh`。

---

## M0 · 内核骨架与架构守卫
**目标**：把六层结构与依赖方向固化下来，防止后续腐化。

| 交付 | 说明 |
|---|---|
| Rust workspace（10 crate） | 见 `06-原型代码/` |
| `neo-protocol` 类型定义 | Op / EventMsg / ContextRef 等 |
| 架构守卫脚本 | `check_architecture.py` |

**验收（必须全绿）**
```bash
bash 05-验证/verify.sh            # 含架构守卫
cd 06-原型代码 && cargo check --workspace   # 需本地 Rust 工具链
```
- [ ] 无向上依赖（如 L2 不得依赖 L3/L4/L5）
- [ ] 依赖图无环
- [ ] 三个宿主 crate 之间无相互依赖
- [ ] `neo-protocol` 无业务 crate 依赖

**DoD**：架构守卫纳入 CI，任何违反依赖方向的 PR 直接失败。

## M1 · 事件协议 + 会话持久化
**目标**：SQ/EQ 跑通，会话可完整重建。

| 交付 | 说明 |
|---|---|
| `submit(Op)` / `next_event()` | L2 内核基础 |
| JSONL append-only 会话存储 | seq 严格递增 |
| golden 回放用例 | `05-验证/golden/` |

**验收**
- [ ] `check_protocol.py`：同一 Op 序列 → 同一 EventMsg 序列（**类型、顺序、ID 规则**确定）
- [ ] `check_session_schema.py`：所有 golden JSONL 通过 schema 校验
- [ ] `seq` 严格递增、无空洞；从 JSONL 可完整重建 Session 状态
- [ ] `Op::Interrupt` 可在工具边界安全中断，无半写状态

## M2 · 沙箱 × 审批正交双轴
**目标**：安全边界可用、可证明。

| 交付 | 说明 |
|---|---|
| 三平台沙箱后端 | Seatbelt / Landlock+bwrap / restricted token |
| ApprovalGate | 双轴判定 |
| 五档执行模式映射 | ZCode UX → 双轴预设 |

**验收**
- [ ] `check_mode_matrix.py`：5 档 × 3 档映射表自洽、无歧义、覆盖完整
- [ ] 真实越权命令被三平台各自拦截（需实机测试，写入测试报告）
- [ ] 无可用沙箱后端 → 返回 `SANDBOX_UNAVAILABLE`，**不裸奔**
- [ ] `workspace-write` 默认断网，开启需显式配置

## M4 · Goal 引擎（Plan→Code→Review→Learn）
**目标**：长程任务可用、可恢复、不失控。

| 交付 | 说明 |
|---|---|
| Goal 拆解与调度 | 任务树 + 依赖排序 |
| 四阶段闭环 | Plan / Code / Review / Learn |
| Checkpoint 链 | 断点恢复 |
| fresh-by-default（BM25 版） | JSONL + 关键词检索 |

**验收**
- [ ] `/goal` 可拆解、暂停、重定向、清除（均不重置会话）
- [ ] **kill 进程后重启能续跑**（核心验收）
- [ ] Review 失败自动回退重做，≤3 次后停止并上报
- [ ] 五项停止条件全部生效，无无限循环
- [ ] `check_config_layers.py`：AGENTS.md 级联优先级正确，超限 32KiB 正确降级

## 全项目级硬指标（贯穿 M0–M6）

| 指标 | 基线要求 | 说明 |
|---|---|---|
| **架构不腐化** | 架构守卫 100% 通过 | 每个 PR 都跑 |
| **协议确定性** | golden 回放 100% 通过 | 新增事件必须补 golden |
| **会话可重建** | JSONL schema 100% 通过 | append-only 不被破坏 |
| **提示词缓存命中率** | ≥ 60%（M4 起可测） | 固定前缀策略的效果验证 |
| **AI 改码一次通过率** | 相对基线 +30% | 需在 M0 前先录基线 |

> ⚠️ **最后一条必须先录基线**：在动手重构前，先记录当前 DSH 二开中 AI 出码的一次通过率。
> 没有基线，事后无法证明重构是否真的改善了"AI 调试慢"这个原始痛点。
