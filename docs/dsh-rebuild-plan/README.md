# DSH 彻底重构方案 · NEO

> **项目代号**：NEO（New Execution Orchestrator）
> **目标**：以 DeepSeek Harness（DSH）为起点，吸收 **智谱 ZCode（Z.ai）** 的交互范式与 **OpenAI Codex CLI** 的运行时架构，**用 Rust 重写内核**，交付 **Web + TUI 双宿主共享同一内核** 的编程 Agent。
> **核心原则**：吸收两者的优秀设计，摒弃 DSH 的冗余过重设计。

## 二、快速开始

```bash
cd 05-验证
bash verify.sh            # 跑全部可执行的架构/协议/会话/配置/模式校验
```

验证套件**不需要 Rust 工具链**，全部为 Python 3 实现，直接可跑。
它验证的是**架构契约与协议语义**，而不是"代码能编译"。

> ⚠️ **关于 Rust 原型**：`06-原型代码/` 是架构骨架与 trait 契约，用于固定分层与接口。
> 沙盒环境无 Rust 工具链（无法联网安装 rustup），因此**未执行 `cargo check`**。
> 在你的机器上需自行运行：
> ```bash
> cd 06-原型代码 && cargo check --workspace
> ```
> 若要做 CI 门禁，把 `cargo check` 追加进 `05-验证/verify.sh` 即可（脚本已预留挂载点）。

## 三、设计立场的三句话

1. **不要"一切皆插件"。** DSH 把 agent loop、UI、存储全做成插件，换来的是极深的调用栈和极难的定位——这在 AI 辅助开发时代是负资产。NEO 改为 **固定内核 + 4 类有限扩展点**（Tool / Skill / Subagent / ModelProvider）。
2. **宿主只是内核的一个消费者。** Web 与 TUI 不持有业务状态，只消费同一条事件流（SQ/EQ）。这是 Codex 多宿主设计的精髓，也是"改 UI 不动内核"的前提。
3. **安全是正交双轴。** 沙箱决定"能做什么"，审批决定"何时必须问"。二者必须独立配置——Codex 用户最常见的困惑就来自把两个旋钮当成一个。

## 四、验收口径（Definition of Done）

见 `04-落地计划/里程碑与验收标准.md`。最硬的三条：

- **架构不腐化**：`check_architecture.py` 通过（无向上依赖、无环）
- **协议确定性**：同一 Op 序列回放得到同一 EventMsg 序列（`check_protocol.py`）
- **会话可重建**：任意 JSONL 会话日志可完整重建状态，且 append-only 不被破坏（`check_session_schema.py`）
