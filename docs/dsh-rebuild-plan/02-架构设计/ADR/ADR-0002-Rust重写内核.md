# ADR-0002：用 Rust 重写内核

- **状态**：已接受
- **关联**：Codex 的 Rust 重写动因

## 背景
DSH 内核为 TypeScript（Node 22.19+，219 包，453K 行）。
Codex CLI 于 2026 年完成 Rust 重写（96%+ Rust），官方动因三条：性能、安全、消除 Node.js 依赖。

## 决策
NEO 内核用 Rust 重写。

## 理由
1. **OS 级沙箱需要系统原语直访**：Seatbelt / Landlock+bwrap+seccomp / restricted token+ACL。Rust 直接调，TS 要绕子进程。
2. **单二进制分发，零运行时依赖**：消除"用户没装 Node / 版本不对"这一整类问题。
3. **并发子 agent**：Rust 真并发，不受 JS 单线程与内存膨胀限制。
4. **编译期内存安全**：安全敏感场景下不是加分项，是必选项。
5. **启动与内存**：对齐 Codex 实测数据（冷启动 ~180ms vs ~1.2s；空闲 ~28MB vs ~120MB）。

## 代价（必须承认）
- **AI 写 Rust 的一次通过率低于 TS**（所有权/生命周期/借用检查），且**每次验证要等编译**（增量 10–60s）。
  这是本项目已确认痛点"AI 调试慢"的**放大器**，必须配套缓解措施。
- 团队若无 Rust 经验，上手约需 2–4 周。

## 缓解措施（强制）
1. **业务逻辑纯函数化**：L2/L4 的可测逻辑抽成不依赖 IO 的纯函数，`cargo test` 秒级验证，不启动完整 agent。
2. **协议层零依赖**：`dsh-protocol` 只有 serde，编译极快，改动频率最高的部分放在这里。
3. **JSONL 回放测试**：继承 DSH 的无 API Key 测试方案，逻辑验证不依赖真实模型调用。
4. **分层编译**：高频改动层（L4/L5）依赖少，增量编译快；重依赖（L0 沙箱）改动频率低。

## 验证方式
`cargo check --workspace` + `cargo test --workspace`（需本地 Rust 工具链）。
沙盒环境无 Rust 工具链，故本包内**未执行**，需在本地补跑。
