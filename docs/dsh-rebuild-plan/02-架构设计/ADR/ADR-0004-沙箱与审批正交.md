# ADR-0004：沙箱与审批必须是正交双轴

- **状态**：已接受
- **关联**：Codex 正交双轴 + ZCode 五档执行模式

## 背景
很多工具把"权限"做成单一档位（suggest / auto-edit / full-auto），导致两个经典困惑：
- 设了"不询问"却发现 agent 还是写不了文件（沙箱仍是 read-only）
- 设了"完全访问"却仍被不停询问（审批策略还是 untrusted）

## 决策
两个**独立**配置维度：
- `sandbox_mode`：**技术上能做什么**（OS 强制，agent 无法绕过）
- `approval_policy`：**流程上何时必须暂停询问**

UI 上暴露为 ZCode 的五档执行模式（计划 / 变更前确认 / 默认 / 自动编辑 / 完全访问），
每档是**双轴的一个预设组合**，但允许高级用户分别配置。

## 理由
1. 语义清晰：一个管能力边界，一个管交互节奏。
2. 沙箱是**安全**手段（不可被审批覆盖），审批是**体验**手段。
3. ZCode 的五档 UX 已被验证易懂，用作前端档位；双轴用作底层语义。

## 附加决策
- **fail-closed**（继承 DSH）：请求受限档位但平台无可用沙箱后端 → 直接拒绝执行，不降级裸奔。
- `workspace-write` 下**默认断网**，需显式开启。

## 验证方式
`check_mode_matrix.py`：校验 5 档模式 × 3 档沙箱的映射表自洽、无歧义、覆盖完整。
