UI 精细度第二步：排版层级（data-driven 角色）+ 间距归到设计系统 scale

继续上一轮的"粗糙清单"，本轮做**字号层级**与**间距 scale** —— 这两项对观感的
贡献比圆角更大。

**审计出的第二个硬数字**：宿主里 `font_weight` / `text_size` 出现 **0 次**，
且间距里有**离 scale 的原始值**（`.py(px(3.))` —— 设计系统的档位是
2/4/8/12/16/24/32，没有 3）。

**改法上刻意避免"逐处挑字号"**（那会得到十几种组合，正是拼凑感）：
新增 `neo_ui::text_role`，按**角色**给样式，且角色是**数据**（`Role { size, bold, tone }`）
而不是写死在函数里 —— 这让"层级存在"成为**可断言的**：
若四个角色被改成同一组值，测试会红；写死在函数里就只能靠肉眼发现"界面又变平了"。

四个角色与依据：
| 角色 | 规格 | 用在 |
|---|---|---|
| `SECTION_TITLE` | 14px + SEMIBOLD + Info | 面板标题（文件树、快捷键、命令数） |
| `BODY` | 16px + 常规 + Text | 正文、文件行、内容 |
| `META` | 14px + 常规 + Muted | 说明文字、路径、时间戳 |
| `TINY` | 12px + 常规 + Muted | 行号、角标 |

数值取自设计系统的 `TypographyTokens`（xs=12/sm=14/base=16）；**标题取"小一号"
而非"大一号"**是工具型界面的惯例（Zed / VS Code）：正文是主角、字号偏小换信息
密度，标题靠字重与颜色区分。

**层级不只靠字重**：结合 §4.64(ba) 的教训（CJK 常无真粗体字面，bold 可能看不出来），
标题同时用更亮的语义色、说明同时用弱化色 —— 两条路径叠加，任一条在某字体上失效
仍可分辨。

间距：5 处离 scale 的原始像素归到 `py_0p5()`（2px）/ `py_1()`（4px），
宿主里已无 raw `px()` 间距。

新增测试 `text_roles_form_a_real_hierarchy`（断言彼此不同 + 标题不比正文大 +
标题加粗 + 三种颜色互不相同）。牙齿已验证：把标题抹平成正文立刻红。

**顺带把上一轮标注为"未测"的暗色对比度补上**：实测 `Text` 17.9 / `Muted` 6.1 /
`Info` 12.6（黑底）与 14.0 / 4.8 / 9.8（面板底），全部 ≥4.5:1（WCAG AA）。
并固化成守卫（`neo-text` 的 `text_and_muted_stay_readable_on_both_backgrounds`）
—— 对比度是**最容易被静默破坏**的观感：调暗 `muted` 看起来更雅致，实际让说明
文字变难读，不报错只费眼。牙齿已验证（调暗到 0x3a 立刻红）。
