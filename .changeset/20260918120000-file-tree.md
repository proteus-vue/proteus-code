D12 文件树：工作区文件索引 + 面板 + 点文件加 `@引用`（并补上引用格式化）

parity 清单里唯一还是 ❌ 的项（D12）做了第一层：**文件树**。

- **`neo-platform::file_index`**（L0，新）：有界的工作区扫描。遵守
  `.gitignore`/`.ignore`、跳过隐藏文件、**绝不跟随符号链接**（终止性要求，
  不是效率优化）、条目/深度/时间三重上限并**如实上报 `truncated`**。
  跨平台可复用（TUI 将来用同一份），避免"什么该忽略"出现第二套实现。
- **`neo-protocol::format_file_ref`**（解析的逆，此前**只有解析没有格式化**）：
  路径含空格时必须 `@"my file.txt"`，否则下次解析会把它切成两个词、静默丢掉引用。
  已用往返用例钉住（含空格/两种引号/全角空格/含 `#` 的路径），并验证过牙齿。
- **gpui 宿主**：`/files` 命令 + 状态栏开关 + 覆盖式面板；点文件**追加**
  引用到输入框（不覆盖用户已写内容）。egui 侧如实提示"仅 gpui 可用"，
  不留"列着却点了没反应"的假功能。

**实测抓到的两个坑**：
1. `ignore` 的 `require_git` **默认 true** —— 非 git 目录里 `.gitignore`
   完全失效（本仓的临时目录测试就是这么红起来的）。文件树必须显式设 false。
2. `NEO_GUI_PANEL=files`（启动即打开）走构造函数、**不经过 `run_action`**，
   于是惰性扫描从未触发、面板永远停在"正在扫描"。改为让"面板可见 ⇒ 索引就绪"
   成为自足条件。

真机验证（按窗口 ID 截图，未抢焦点）：树正确渲染，`debug.log` 与
`target/debug/big.bin` 被正确排除、`.gitignore` 自身不可见。
扫描准确性另与 `git ls-files` 交叉核对：本仓 342 个文件 vs git 跟踪的非隐藏
341 个，唯一差异是当时未跟踪的新文件 —— 既无泄漏也未过度排除。

**诚实边界**：不做文件监听（会话中途新建的文件需点"刷新"）；不画可折叠树
（层级由路径表达）；点击是"加引用"而非"打开文件"（内置浏览器仍未做）。
