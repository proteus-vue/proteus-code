D12 可折叠文件树：把"一堵路径墙"变成层级（默认全折叠）

文件树此前渲染**扁平全路径**。在真实仓库上这是"路径墙"：本仓 342 个文件
排成一列，且每行重复长前缀（`crates/neo-platform/src/`），横向空间几乎全花在
重复信息上。Zed / VS Code / ZCode 都用缩进树 + 可折叠。

新增 `neo-ui-behavior::tree`（纯逻辑，两个宿主共用）：
- **默认全折叠**（只显示根级）—— 这是本模块存在的直接理由：默认全展开的话
  342 个文件仍是一堵墙（只是换了缩进），等于没做；
- 只显示**确实含文件**的目录（目录集合从文件路径派生，不额外收一份）；
- 同级内**目录在前**，各自按名字排序；
- 缩进**有上限**（8 级）—— 极深路径会把名字挤出面板右边界，那时缩进反而挤掉内容。

宿主：目录用 ▸/▾ + **直接子项数**（"点开一下会多出几行"可预期）、缩进渲染、
点目录切换展开/点文件预览；面板加"展开全部 / 全部折叠"一键开关。

**真实仓库实测**（本仓路径清单）：折叠态 **16 行**（6 个根级目录 + 10 个根级文件）、
全展开 **465 行 = 344 文件 + 121 目录**（内部自洽），目录确实都在文件之前。

展开状态**按路径记**（不按下标）：文件列表会被重扫（点刷新、将来接文件监听），
下标会整批错位 —— 那时"我展开的目录"会变成别的目录。重扫时按路径保留、
并清掉已不存在的目录。

13 条纯逻辑测试 + 2 条宿主接线测试（折叠态行数、展开一层不显孙项、
重扫后按路径保留）。真机截图确认：真实仓库上折叠态是 7 行而不是 342 行。
