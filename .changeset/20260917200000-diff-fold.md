diff 未改区块折叠：行为层新增可折叠逻辑（对当前 diff 形状**休眠**，据实标注）

新增 `neo-ui-behavior::fold`：把长 diff 里成片的未改上下文收成一行"⋯ 未改 N 行
（点击展开）"把手。三条语义都钉了测试：① 只折 `Context`，`Header`（文件头）与
`Meta`（"…另有 N 处"截断说明）**绝不折** —— 折了会把「这段属于哪个文件」
「这个 diff 被截断过」藏掉；② 折了必须**真的净省行数**（折 3 行多一个把手是负收益）；
③ 紧邻改动的上下文保留 3 行（理解改动需要它）。另钉住"折叠只隐藏、绝不重排"。

为支撑①，`DiffBand` 从"改动色 / 其它"补成**完整分类**（新增 `Header` / `Meta` /
`Fold`）—— 曾经的 `_ => Context` 会把结构行混进可折的上下文。宿主侧分类+
折叠抽成纯函数 `diff_display_rows`，并断言"底带必须与显示行同长"（折叠改变了
显示行数，底带沿用原行数就会错位）。

**⚠️ 诚实边界：对我们自己生成的 diff，折叠是休眠的。** 实测
`neo-capability::diff::unified_diff` 每 hunk 只带 `CONTEXT = 3` 行上下文，
最长连续上下文就是 3 行 < 阈值 6，故**永不触发**。已用测试钉住这个事实
（`our_own_diff_shape_does_not_fold`），防止有人为了让功能"看起来在工作"而
调低阈值（那是负收益）。它会在"上下文半径调大 / 喂进完整上下文 diff /
并排视图"任一情况出现时立刻生效，不需改本模块。

真机验证（**按窗口 ID 截图，不抢用户焦点**）：全文件写入型 diff（30 删除行）
底带逐行对齐、无折叠行 —— 与"休眠"的判断一致。宿主接线另用 3 条无头测试证明
（人工喂长上下文时会真的折、展开态全部铺开且保留把手、底带始终同长）。
